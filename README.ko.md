# LabHarbor

공유 GPU 서버를 연구실·계정·GPU·저장공간 단위로 관리하는 대시보드입니다.

## 사용 흐름

1. 전체 자원 지도에서 서버 상태와 연구실별 자원을 확인합니다.
2. 연구실을 선택한 뒤 계정, 자원, 이미지, 백업, 환경 안내서로 들어갑니다.
3. CPU·메모리는 슬라이더 또는 숫자로 입력합니다. 적용 전 대상 계정을 확인합니다.
4. 환경 안내서는 접속 주소·계정·자원·개발 환경을 담는 한국어/영어 PDF입니다.

화면은 5초마다 바뀐 값만 갱신하고, 숨겨진 탭에서는 조회를 중지합니다. 언어는 브라우저 설정을 따르며 상단에서 변경할 수 있습니다.

## 설치

Linux/systemd, Docker, NVIDIA 드라이버·Container Toolkit, Python 3.10~3.12와 venv가 필요합니다.

```sh
sudo python3 install.py --check
sudo python3 install.py
```

관리자 계정, 접속 IP·포트, 백업 경로, 변경을 허용할 GPU를 입력합니다. 설치 후 브라우저의 '기존 환경 등록'에서 실행 중인 컨테이너를 연구실로 연결합니다. 설치 과정에서 연구원 컨테이너나 Docker 서비스를 재시작하지 않습니다.

## 지원 범위

- 컨테이너 재시작 없는 CPU·메모리 한도 조정. 실행 중 메모리 축소는 차단합니다.
- 기존 ext4 루프 장치 구성에 한해 공유 저장공간 확대를 지원합니다. 새로 등록한 임의 저장장치는 자동 확장하지 않습니다.
- 공식 NVIDIA CUDA/PyTorch 태그 조회와 프리셋 저장. 이미지 다운로드·교체는 수행하지 않습니다.
- 영구 `/home`, 쓰기 가능한 계정 설정, 제한 없는 SSH 계정 허용 구성을 갖춘 컨테이너에 한해 내부 계정을 추가합니다.
- 컨테이너 파일시스템과 영구 저장공간의 무중단 파일 백업. 실행 중 변경된 파일의 동일 시점 일관성은 보장하지 않습니다.

GPU 할당 변경과 기본 이미지 교체에는 재생성이 필요하므로 실행하지 않습니다. 현재 읽기 전용 1인 1컨테이너 환경에 계정을 추가하거나 루트 권한을 부여하는 기능도 실행하지 않습니다. 프리셋의 내부 관리자 권한은 요청 설정일 뿐 실제 권한 변경이 아닙니다.

## 업데이트

```sh
sudo python3 install.py --update
```

대시보드 서비스만 재시작하고 서버별 설정은 유지합니다. 이전 앱은 복구용으로 보관합니다. 다른 실제 서버에서의 신규 설치와 백업 복원은 아직 실기 검증하지 않았습니다.
